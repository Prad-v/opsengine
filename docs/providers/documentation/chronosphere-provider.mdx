## Overview

[Chronosphere](https://chronosphere.io/) Observability Platform can send alert notifications to Keep using a **Webhook notifier**.
The payload is Prometheus Alertmanager-compatible and includes Chronosphere-specific fields such as `notifier`, `monitor_slug`, and webhook signature headers.

Official reference: [Create a webhook notifier](https://docs.chronosphere.io/investigate/alerts/notifications/notifiers/webhook).

## Connecting Chronosphere to Keep

### 1. Create a Keep webhook API key

In Keep, open **Settings → API Keys** and create (or reuse) an API key with the `webhook` role.

### 2. Create a Chronosphere webhook notifier

In Chronosphere Observability Platform:

1. Go to **Alerting → Notifiers**.
2. Click **Create notifier**.
3. Choose **Webhook**.
4. Set the URL to your Keep backend:

```text
https://KEEP_API_URL/alerts/event/chronosphere
```

5. Authenticate the request using one of:

| Method | Configuration |
| --- | --- |
| Basic auth | Username `keep`, password `<KEEP_WEBHOOK_API_KEY>` |
| URL query | `https://KEEP_API_URL/alerts/event/chronosphere?api_key=<KEEP_WEBHOOK_API_KEY>` |
| Bearer token | `Authorization: Bearer <KEEP_WEBHOOK_API_KEY>` |

6. Optional: enable **Notify when resolved** so resolved alerts clear in Keep.
7. Save the notifier and attach it to a notification policy.

### Chronoctl example

```yaml
api_version: v1/config
kind: Notifier
spec:
  name: keep-webhook
  slug: keep-webhook
  skip_resolved: false
  webhook:
    url: https://KEEP_API_URL/alerts/event/chronosphere
```

Apply with:

```bash
chronoctl apply -f keep-webhook-notifier.yaml
```

Configure HTTP basic auth or bearer token on the notifier (UI / Terraform / API) using your Keep webhook API key.

### Terraform example

```terraform
resource "chronosphere_webhook_alert_notifier" "keep" {
  name           = "Keep Webhook"
  slug           = "keep-webhook"
  url            = "https://KEEP_API_URL/alerts/event/chronosphere"
  send_resolved  = true
  basic_auth_username = "keep"
  basic_auth_password = var.keep_webhook_api_key
}
```

## Webhook payload

Chronosphere posts a body similar to:

```json
{
  "notifier": "test webhook",
  "status": "firing",
  "alerts": [
    {
      "status": "firing",
      "labels": {
        "alertname": "test alert",
        "severity": "critical"
      },
      "annotations": {
        "monitor_slug": "test-monitor",
        "notification_policy_slug": "test-policy"
      },
      "startsAt": "2020-05-19T13:57:21.68227886Z",
      "endsAt": "0001-01-01T00:00:00Z",
      "fingerprint": "7424223989b20025"
    }
  ],
  "groupLabels": {},
  "commonLabels": {},
  "commonAnnotations": {},
  "version": "4"
}
```

Keep maps each entry in `alerts` to an alert with source `chronosphere`, including labels, severity, fingerprint, and Chronosphere annotation fields (`monitor_slug`, `notification_policy_slug`, `ruleid`).

## Webhook signatures (HMAC)

Chronosphere signs every outbound webhook with:

- `Chronosphere-Webhook-Timestamp` — Unix timestamp
- `Chronosphere-Webhook-Signature-V1` — hex-encoded HMAC-SHA256 digests (comma-separated, trailing comma)

Signature payload:

```text
v1:<timestamp>:<request_body>
```

### Enable verification in Keep

1. In Chronosphere, open **My Account** and copy the **Webhook Signing Key** (SysAdmin role).
2. In Keep, install/configure the **Chronosphere** provider and set **signing_key** to that value.
3. Point the Chronosphere notifier at the Keep webhook URL that includes `provider_id` (from the provider webhook settings panel), for example:

```text
https://KEEP_API_URL/alerts/event/chronosphere?provider_id=<PROVIDER_ID>
```

4. Authenticate with the Keep webhook API key as usual (basic auth / bearer / query param).

When `signing_key` is configured, Keep verifies the Chronosphere HMAC headers on every request and returns **401** for missing, invalid, or stale signatures (default max age: 15 minutes). If no signing key is configured, verification is skipped and only the Keep API key is required.

Allowlist Chronosphere outbound IPs as documented by Chronosphere if your network requires it.
