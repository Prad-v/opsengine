## Overview

[Temporal](https://temporal.io/) is a durable execution platform for reliable workflows. The Temporal provider lets Keep **start, signal, cancel, terminate, describe, and query** Temporal workflows from Keep workflow actions and steps.

Typical use: an incident or alert arrives in Keep → a Keep workflow matches the trigger → a Temporal action starts a remediation workflow on your Temporal cluster.

## Connecting with the Provider

1. Install Keep with the `temporalio` Python dependency (included in Keep's `pyproject.toml`).
2. In Keep UI → **Providers**, connect **Temporal** with:
   - **address**: Temporal frontend `host:port` (for example `localhost:7233` or `your-namespace.a1b2c.tmprl.cloud:7233`)
   - **namespace**: Temporal namespace (`default`, or `<namespace_id>.<account_id>` for Temporal Cloud)
   - **api_key**: Temporal Cloud API key (optional; enables TLS)
   - **tls** / mTLS PEM fields when connecting with certificates

Provider config is **connection only**. Register workflows under **Catalog → Temporal workflow** (see [Temporal workflow catalog](/overview/temporal-workflow-catalog)).

### Workflow catalog (Keep-managed registry)

Do **not** put workflow definitions on the Temporal provider. Instead:

1. Connect Temporal under **Providers**
2. Open **Catalog → Temporal workflow**
3. Click **Register workflow** and set `name`, `workflow_type`, `task_queue`, provider, and optional `input_mapping`

Keep auto-generates `catalog_key` from the name and uses workflow id template `incident-{{incident.id}}-{{catalog.id}}` when starting runs.

Example fields:

| Field | Required | Purpose |
| --- | --- | --- |
| `name` | yes | Display name (also used to generate `catalog_key`) |
| `catalog_key` | no | Stable catalog id; auto-generated from name if omitted |
| `description` | no | Shown in Catalog and incident registration |
| `workflow_type` | yes | Temporal workflow type name |
| `task_queue` | yes | Temporal task queue |
| `provider_id` | yes | Connected Temporal provider to use |
| `workflow_id_template` | no | Defaults to `incident-{{incident.id}}-{{catalog.id}}` |
| `input_mapping` | no | Maps Temporal input keys → incident field paths (`id`, `name`, `severity`, `enrichments.foo`, …) |

On an incident’s **Workflows** tab, Keep lists registered catalog entries and **Start for incident** starts the Temporal run and enriches the incident with `temporal_workflows` (workflow id / run id / catalog id).

API: `GET/POST/PUT/DELETE /temporal-workflows` and `POST /temporal-workflows/{id}/start`.
### Local Temporal (Docker Compose)

Keep ships `docker-compose.temporal.yml` with:

- Temporal server (`localhost:7233`, UI http://localhost:8233)
- **temporal-worker** on task queue `keep-ops` running workflow **`ListAndZipDirectory`**
  (runs `ls`, captures output, writes a zip under `/data/output`)

It starts automatically with:

```bash
make deps    # hybrid local deps (+ worker)
make up      # full Docker dev stack
make local   # production Dockerfiles from this checkout
```

Or standalone:

```bash
docker compose -f docker-compose.temporal.yml up -d --build
# or
make temporal-worker
```

Register the demo workflow in Keep’s catalog (Temporal provider must be connected):

```bash
make register-list-and-zip-catalog
```

Then open an incident → **Workflows** → **Start for incident** on **List and Zip Directory**.
Optional enrichment `list_path=sample` lists `/data/sample` inside the worker (default).

| Endpoint | Address |
| --- | --- |
| Frontend (gRPC) | `localhost:7233` (from host) / `temporal:7233` (from Keep containers) |
| Web UI | http://localhost:8233 |
| Namespace | `default` |
| Worker queue | `keep-ops` |

Connect the Temporal provider with `address: localhost:7233`, `namespace: default`, and TLS disabled.

### Temporal Cloud

Use your gRPC namespace endpoint, namespace id + account id, and an API key (or mTLS certs). TLS is enabled automatically when `api_key` is set.

## Start a Temporal workflow when an incident is created

```yaml
workflow:
  id: incident-to-temporal
  name: Start Temporal remediation on incident
  description: Starts a Temporal workflow whenever a Keep incident is created.
  triggers:
    - type: incident
      events:
        - created
  actions:
    - name: start-temporal-remediation
      provider:
        type: temporal
        config: "{{ providers.my-temporal }}"
        with:
          operation: start_workflow
          workflow_type: RemediateIncident
          task_queue: keep-ops
          workflow_id: "incident-{{ incident.id }}"
          arg:
            incident_id: "{{ incident.id }}"
            name: "{{ incident.name }}"
            severity: "{{ incident.severity }}"
```

## Start a Temporal workflow on an alert

```yaml
workflow:
  id: alert-to-temporal
  name: Start Temporal workflow on critical alert
  triggers:
    - type: alert
      cel: severity == "critical"
  actions:
    - name: start-temporal
      provider:
        type: temporal
        config: "{{ providers.my-temporal }}"
        with:
          workflow_type: HandleAlert
          task_queue: keep-ops
          workflow_id: "alert-{{ alert.fingerprint }}"
          arg: "{{ alert }}"
```

## Query workflow status (step)

```yaml
steps:
  - name: describe-run
    provider:
      type: temporal
      config: "{{ providers.my-temporal }}"
      with:
        operation: describe_workflow
        workflow_id: "incident-{{ incident.id }}"
```

## Supported operations

### Actions (`_notify`)

| operation | Required fields | Purpose |
| --- | --- | --- |
| `start_workflow` (default) | `workflow_type`, `task_queue` | Start a workflow (`workflow_id`, `arg` / `args` optional) |
| `signal_workflow` | `workflow_id`, `signal_name` | Signal a running workflow |
| `cancel_workflow` | `workflow_id` | Request cancel |
| `terminate_workflow` | `workflow_id` | Terminate |

### Steps (`_query`)

| operation | Required fields | Purpose |
| --- | --- | --- |
| `describe_workflow` (default) | `workflow_id` | Describe a run |
| `query_workflow` | `workflow_id`, `query_name` | Run a workflow query |
| `list_workflows` | optional `query`, `page_size` | List workflows |
