## Goal

Prove the AI datacenter remediation path:

1. **Provider mock** fires NVIDIA / DCGM VictoriaMetrics (VMAlert) alerts into Keep  
2. Keep correlates them into a **GPU** incident  
3. Keep workflow starts Temporal **`RemediateNvidiaGpu`**  
4. Temporal runs the GPU path:  
   - Optional / auto **approval** for suite L3+  
   - **Cordon + drain** for suite L2+  
   - Mock **`dcgmi diag`** (`POST /gpu/server/diag`)  
   - **Pass / RESET** → remediates → uncordon → resolves the Keep incident  
   - **Fail / ISOLATE** → mock ops email; node stays cordoned; incident stays open

## One-command setup

`make start` already:

- Starts provider-mock (`:8099`) and the Temporal worker (`RemediateNvidiaGpu`)
- Registers **mock-victoriametrics** + **mock-temporal** into Keep (best-effort)
- Registers **Remediate NVIDIA GPU** in the Temporal catalog
- Registers reserved **DCGM_*** codes (exporter metrics + diag plugins + `DCGM_FR_*`) under Catalog → Alert codes
- Uploads `examples/workflows/mock-nvidia-gpu-remediate.yml`
- Seeds **Service Topology** (region / datacenter / row / rack / GPU)

To re-run only the GPU demo setup after Keep is up:

```bash
make demo-nvidia-gpu
```

Disable auto-setup: `AUTO_SETUP_NVIDIA_GPU_DEMO=0 make start`

## Fire the demo

1. Mock UI → **VictoriaMetrics** → **Register**  
2. Mock UI → **Temporal** → **Register Temporal**  
3. Keep → **Service Topology** — filter **NVIDIA GPU Inference** (seeded by `make start`)  
4. Success path: VictoriaMetrics → **GPU: rule + temp/mem**  
5. Failure path: **NVIDIA GPU server** tab → enable **Force fail**, then re-fire GPU alerts  

## What to check

| Place | Success | Failure (`Force fail`) |
| --- | --- | --- |
| **Incident** | Status becomes **resolved** | Stays open |
| **Incident → Workflows** | Keep workflow + Temporal start | Same |
| **Incident → Overview** | `gpu_remediation=started`, `gpu_diag_suite=2` | Same |
| **Mock → Lifecycle** | cordon → … → uncordon | cordon (stays cordoned) |
| **Mock → DCGM diagnostics** | `Pass` → `RESET` | `Fail` → `ISOLATE` (`DCGM_FR_FAULTY_MEMORY`) |
| **Mock → Remediations** | `reset_gpu` **ok** | Empty for this run (isolate skips reset) |
| **Mock → Failure emails** | Empty (or prior) | New email to `ops@ai-dc.local` |
| **Keep → Service Topology** | `gpu-inference` + `gpu-node-a03` / `rack-12` / `row-a` badge | Same path, incident stays open |
| **Temporal UI** http://localhost:8233 | Workflow `RemediateNvidiaGpu` completed | Completed with `ok=false`, `reason=diag_isolate` |

## Workflow file

[`examples/workflows/mock-nvidia-gpu-remediate.yml`](https://github.com/keephq/keep/blob/main/examples/workflows/mock-nvidia-gpu-remediate.yml)

- Triggers: alert CEL `labels.code.startsWith("DCGM_")` **or** incident `created` / `updated` with the same code filter  
- Guard: enrichment `gpu_remediation` not set  
- Action: Temporal `start_workflow` → `RemediateNvidiaGpu` / `keep-ops` with `suite: "2"` (medium: software + memory + pcie)  
- Mock payloads set reserved `labels.code` to the DCGM metric name (`DCGM_FI_DEV_GPU_TEMP`, `DCGM_FI_DEV_FB_USED`, …). `make start` / `scripts/register_alert_codes_nvidia_gpu.py` seeds exporter metrics (aligned to dcgm-exporter help text + detection notes), diag plugins (`DCGM_DIAG_*`), and finding codes (`DCGM_FR_*`, including health-watch codes like `DCGM_FR_FALLEN_OFF_BUS`) under [Catalog → Alert codes](/overview/alert-code-catalog).  
- Temporal: cordon (L2+) → `run_dcgm_diag` → Pass: remediate + uncordon + resolve; Fail: email only  
- Suite L3+ (`3` / `long` / `4` / `xlong`) auto-creates a Keep **Approvals** request unless `skip_approval: true`

## DCGM diagnostics (mock + real)

| Suite | Plugins (mock) | Cordon | Approval | Typical use |
| --- | --- | --- | --- | --- |
| `1` / `quick` | `software` | no | no | Pre-flight / thermal soft alerts |
| `2` / `medium` | `software`, `memory`, `pcie` | yes | no | Default confirm before reset |
| `3` / `long` | + compute / bandwidth / stress / power | yes | **yes** | After L2 or NVLink alerts |
| `4` / `xlong` | + `memtest`, `pulse_test` | yes | **yes** | Burn-in |

Pass → recommendation **RESET**. Force-fail → **ISOLATE** with `DCGM_FR_FAULTY_MEMORY`.

Set `DCGM_DIAG_MODE=real` on the Temporal worker to run `dcgmi diag --run … --json` on the worker host (falls back to mock if `dcgmi` is missing unless `DCGM_DIAG_REQUIRE_REAL=1`). Pin DCGM versions — JSON is not a stable public schema.

Passive exporter scrapes (`/api/synth/nvidia/dcgm/metrics`) are a separate canary — see [AI DC synthetics](/overview/ai-dc-synthetic-checks).
