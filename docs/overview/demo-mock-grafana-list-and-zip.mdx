## Goal

Prove the hybrid path:

1. **Keep** detects/correlates mock Grafana alerts into an incident  
2. **Keep workflow** starts a **Temporal catalog** workflow (`ListAndZipDirectory`)  
3. You inspect the **incident Timeline / Workflows / Overview**

## One-command setup

With Keep already running (`make start`):

```bash
make demo-list-and-zip
```

This:

- Starts/rebuilds the Temporal worker  
- Registers **List and Zip Directory** in the catalog  
- Registers reserved codes `HIGH_CPU` / `HIGH_MEMORY` / `DISK_SPACE_LOW`  
- Uploads `examples/workflows/mock-grafana-list-and-zip.yml`

## Fire the demo

Provider mock is already up with `make start` at [http://localhost:8099](http://localhost:8099). Restart only if needed: `make mock-providers`.

1. Mock UI → **Grafana** → **Register**  
2. Mock UI → **Temporal** → **Register Temporal**  
3. Grafana → **Payments: rule + send both**

Keep correlates `HIGH_CPU` + `HIGH_MEMORY` into one incident (group by `labels.service`). GPU alerts use `NVIDIA_GPU_*` and a different workflow — see [GPU remediate demo](/overview/demo-mock-nvidia-gpu-remediate).

## What to check

| Place | What you should see |
| --- | --- |
| **Incident → Timeline** | The two Grafana mock alerts (`HIGH_CPU` / `HIGH_MEMORY`) |
| **Incident → Workflows** | Keep workflow run for `Mock Grafana → Temporal ListAndZip` |
| **Incident → Overview** | Enrichments `remediation`, `list_path`, `temporal_demo` |
| **Temporal UI** http://localhost:8233 | Workflow `ListAndZipDirectory` on queue `keep-ops` |
| Worker output | `docker exec keep-temporal-worker ls -la /data/output` |

> **Timeline vs Activity:** Keep’s **Timeline** tab is alert history (what the mock fires). Keep’s **Activity** tab is comments/status/assign — this demo does not auto-post comments (HTTP to `localhost` is blocked by Keep’s SSRF guard). Use **Workflows** + **Overview** for the Temporal breadcrumb.

## Workflow file

[`examples/workflows/mock-grafana-list-and-zip.yml`](https://github.com/keephq/keep/blob/main/examples/workflows/mock-grafana-list-and-zip.yml)

- Trigger: `incident` created **or** updated, CEL on reserved codes `HIGH_CPU` / `HIGH_MEMORY`  
- Guard: `not '{{ incident.temporal_demo }}'` so Temporal starts once  
- Action: Temporal `start_workflow` → `ListAndZipDirectory` / `keep-ops`  
- `enrich_incident` breadcrumbs for Overview  
- Console log of the start  

## Builder alternative

Instead of (or in addition to) the YAML action, use **Add step → Temporal catalog → List and Zip Directory** in the Keep workflow builder — same catalog entry, pre-filled Temporal fields.
